## Review Coverage

Collection prioritizes original incident response, malware reverse engineering, government notices, corporate disclosures and dated tracker pages. Aggregators and press are used for discovery, current counts or case chronology, not to create technical behavior by repetition.

The following searches did not produce actor-specific public evidence and are documented as gaps: a dedicated MITRE object, a direct CrowdStrike name for DragonForce core, a direct Mandiant core-service name, a public Chainalysis/Elliptic wallet trace, an OFAC designation, a verified PDB path and detailed NAS reverse engineering.

Tracker data was captured on 2026-09-24. Infrastructure status and totals can change after that date. External YARA rules remain linked at their publisher; local rules are independently written so their logic and limitations can be reviewed here.

## Executable Analysis Provenance

The LockBit-derived file is based principally on DF009 and DF019, with DF020/DF035 used for sample and artifact cross-checking. The Conti-derived file is based principally on DF018. The 2026 panel-builder revision uses DF059 and DF060. The Linux/ESXi file uses DF009, DF059 and victim-recovery distinctions from DF018. CISA and Microsoft sources establish deployment context but are not used to invent binary internals.

The Windows 534-byte footer belongs to the earlier S2W-analyzed Conti-derived build. The later panel beta expands the ratio field from one to four bytes and appends 537 bytes; S2W’s victim-specific Windows decryptor reads the same total. The ESXi recovery branch validates an additional eight-byte build key and reads 512 bytes of protected metadata. Algorithms, thresholds and extensions are kept sample-scoped. No malware binary was downloaded or executed.
